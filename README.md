# CUE LAB · 台球实验室

**一款带智能击球辅助的浏览器 2D 桌球游戏。选目标球、选洞口，探索同一杆的不同解法。**

支持中式八球、自由练习和本地双人对战。你可以手动控制方向、力度、高低杆与左右塞，也可以让程序试算多个合法方案，比较击球复杂度、白球走位和参数容错，再选择执行。

使用 **TypeScript · Canvas 2D · Web Worker · Web Audio**，面向电脑端 Chrome / Edge。游玩、轨迹预览与辅助搜索均在浏览器本机完成，无需登录、服务端计算或外部 AI 接口。

## 能玩什么

| 功能 | 当前实现 |
| --- | --- |
| 中式八球 | 开球、分组、轮流击球、犯规自由球、指定洞口打黑八；支持自由练习和本地双人对战 |
| 手动击球 | 点击或按住拖动瞄准，精细角度调整，力度滑块，击点控制高杆、低杆和左右塞 |
| 特殊杆法 | 手动及智能搜索跳球、扎杆，调整抬杆角度与偏心击点，并查看模拟轨迹 |
| 智能辅助 | 搜索直接进球、单库与双库翻袋/解球、简单组合球及跳球、扎杆；自动选择方向、力度、组合击点与抬杆角度，最多展示 8 个不同方案 |
| 方案比较 | 合法性筛选，按复杂度、下一杆优势、容错、综合评分或最花哨排序；显示完整击球事件链条 |
| 轨迹预览 | 查看本杆受影响球的路线、目标球路径和白球最终落点；支持白球走位预览开关 |
| 击球反馈 | 完整长度球杆的后拉、出杆和收杆动画；随撞击强度变化的击球、碰球、碰库和落袋音效 |
| 球面与落袋 | 球号和条纹随三维姿态滚动；白球红点可切换；击点窗口从球杆视角同步显示旋转；进袋后向隐藏通道滚动，逐渐被袋口遮住 |
| 练习工具 | 多种内置练习局面，自由摆球、移出和恢复球、放置白球，以及撤销 |

**全自动执行**：勾选后，搜索完成即执行排名第一的方案。每次搜索仍由你指定目标球和洞口。

## 本地运行

安装 [Node.js](https://nodejs.org/) 后，在项目目录执行。推荐 Node.js 22.12+，也支持 20.19+。

```bash
npm ci
npm run dev
```

打开终端显示的地址，默认是 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。Windows 用户也可双击 `启动游戏.cmd`，自动安装缺失依赖、启动服务并打开浏览器；关闭终端即可停止服务。

构建与预览生产版本：

```bash
npm run build
npm run preview
```

构建产物位于 `dist/`，可部署到支持静态文件的托管服务。页面须通过 HTTP / HTTPS 访问，直接双击 `index.html` 无法加载模块和 Worker。

## 第一次试用

1. 从球桌下方的练习局面菜单选择 **直球与走位**。
2. 点击彩球选择目标，点击球洞选择目标洞口。
3. 点击右侧 **搜索击球方案**，等待候选方案生成。
4. 选择方案，查看球桌上的轨迹、白球落点、评分与击球链条。
5. 点击 **执行此方案**，或修改力度和击点后手动出杆。
6. 切换到 **翻袋练习 / 单库解球 / 组合球练习 / 跳球练习 / 扎杆练习**，探索不同路线与杆法。

## 操作速查

| 操作 | 作用 |
| --- | --- |
| 点击 / 按住拖动空白台面 | 调整击球方向 |
| 点击彩球 / 球洞 | 选择搜索目标球 / 洞口，同时指定本杆黑八洞口 |
| `←` / `→` | 每次微调方向 0.02°；按住 `Shift` 为 0.005° |
| 方向输入框 | 直接输入角度 |
| 力度滑块 | 默认调整 1–100% 力度；勾选「力度无限制」后可超过 100% |
| 力度无限制 | 滑杆初始扩展到 300%，可继续扩大范围或直接输入更高力度；CPU / GPU 搜索同步考虑当前范围 |
| 拖动杆头击点 | 调整高低杆、左右塞，可叠加 |
| 杆法与抬杆角度 | 选择平杆、跳球、扎杆 |
| 预览本杆 | 显示当前参数的模拟路线；白色虚线为白球，金色实线为目标球，淡色线为其他受影响球 |
| 白球走位 | 调整参数时显示模拟路线及白球落点 |
| 音效 / 红点 | 球桌上方切换音效；杆头击点窗口切换白球旋转标记 |
| `Space` | 出杆 |
| `Ctrl+Z` / `Cmd+Z` | 撤销 |
| `Esc` | 取消搜索或退出摆球 / 放置模式 |

输入框内不会触发出杆快捷键。犯规获得自由球后，点击台面合法位置放置白球；练习模式也可主动放置白球。

## 智能辅助如何工作

搜索先根据球位生成几何候选路线，包括直接进球、单库与双库翻袋/解球、简单组合球；对平杆、跳球和扎杆分别粗搜方向、力度、高低杆与左右塞组合、抬杆角度，再对成功候选和接近目标的失败候选做局部细化。跳球与扎杆的种子也会考虑白球直线受遮挡的局面；是否跳过遮挡、产生弧线、合法首碰与进指定袋，由实际物理模拟确认。搜索不固定为手动面板当前的杆法、击点或抬杆角度。

**力度无限制默认关闭。** 开启后，手动力度不再受 100% 上限限制；滑杆先扩展到 300%，「扩大滑杆范围」按钮可继续翻倍，数值输入也会自动扩大滑杆范围。CPU 与可选 GPU 搜索保留原来的低力度候选，并为平杆、跳球、扎杆加入更高力度候选和局部细化。每次搜索仍只探索当前滑杆范围内的有限候选，扩大范围会增加计算量，也不保证所有局面都能找到解法。关闭后手动力度回到不超过 100%，并清除此前的搜索结果。

**GPU 加速为可选项，默认关闭。** 勾选后，WebGPU 会并行模拟候选击球的粗略轨迹，包含球间碰撞、旋转摩擦、碰库、袋口和跳球高度。每条路线保留评分较好的候选和部分探索候选，再交给原 CPU 引擎精确验证、细化、规则检查和排序；平杆、跳球、扎杆分别筛选。界面显示实际采用的搜索方式与回退原因。

评分权重、候选缓存和去重、方案多样性筛选及最终排序流程见[搜索方案评分与排序维护文档](docs/search-ranking.md)。修改这些搜索逻辑时请同步更新该文档。

GPU 不可用、初始化或运行失败时自动使用完整 CPU 搜索；筛选后未找到合法方案时也会用完整 CPU 搜索补查。GPU 粗略模拟的步进和碰撞处理与精确引擎不同，筛选可能改变方案数量、杆法覆盖和排序，并不保证与完整 CPU 搜索相同。加速收益取决于设备、球局和首次着色器编译成本，简单局面可能没有收益。WebGPU 需要支持的浏览器和安全上下文（HTTPS 或 localhost）；取消勾选即可使用原 CPU 搜索。

搜索的最终验证、预览和实际出杆使用同一物理引擎。只有进入指定洞口、停止运动且通过当前规则检查的方案才会入选，再按路线、杆法与白球落点保留不同方案。每种找到合法解的杆法保留一个代表方案，其余位置按评分和差异筛选，最终按所选偏好排序。方案详情显示自动选出的杆法、击点与抬杆角度。

- **复杂度**：考虑碰球与碰库次数、加塞、高低杆、跳球、扎杆、抬杆角度和大力度等因素，分数越低越简单。
- **最花哨**：优先提高复杂度，额外奖励影响到更多球、碰撞链更长、使用跳球或扎杆、偏心击点以及翻袋、解球和组合球路线；仍只展示合法进袋方案。
- **走位**：评估下一球的直球可打性、距离、切球角度、遮挡与白球贴库情况，分数越高越有利；导致换人时反向评估对手的机会。
- **容错**：对方向、力度、左右击点、高低击点和抬杆角度做 12 次小幅扰动，统计仍能合法完成目标的比例，分数越高越稳定。

走位分数目前使用几何评估，尚未实际搜索下一杆或推演整局；容错分数也不代表真实世界的进球概率。搜索在一个 Web Worker 中运行，可查看进度并立即取消。

## 规则与实现范围

本版采用固定的**中式八球休闲规则约定**，适合练习和本地游玩。

<details>
<summary>展开查看本版规则</summary>

1. 开球需进球或至少四颗目标球碰库，否则犯规。开球进球不分组；开球黑八入袋或离台重置黑八。合法开球进球继续。
2. 开放球局可先碰任一非黑八目标球；非开球时合法打进单一组别后分组，两组同时入袋仍为开放。
3. 分组后先碰己方球；清空己方球后才可首先击打黑八。合法进己方球继续，否则换人。
4. 白球落袋、先碰错球、空杆、球离台、碰球后既无进球也无碰库均为犯规，对方全台自由球。
5. 打黑八前己方球须在上一杆结束后已清空，并指定黑八洞口。提前进黑八、进错袋、打飞黑八或进黑八同时犯规判负。
6. 打飞或犯规打进的普通目标球不重置。尚未实现推杆、连击、故意犯规和三犯裁判机制。

</details>

物理引擎包含球间旋转传递、滑动与滚动摩擦、碰库旋转、袋口斜切袋牙反弹，以及离台重力与落地效果。在每个固定物理步内连续检测接触，按发生顺序处理碰球、碰库和进袋，避免高速薄球漏碰和贴库球穿库。采用近似模型，尚未对照真实球台做专业校准；落袋动画属于视觉反馈，不是精细球袋内部物理。

当前仍有以下边界：

- 跳球与扎杆使用有限方向和角度种子；路线目前覆盖最多双库翻袋/解球和简单组合球，三库以上、连续跳跃和复杂多球组合未系统枚举。
- 有限候选搜索未找到方案时，局面仍可能有其他解法。
- 已实现可选 WebGPU 轨迹粗筛，最终方案仍由原 CPU 物理和规则引擎验证；尚未实现 WebAssembly、电脑对手或联网对战。
- 尚无跨刷新存档；刷新页面会重新开局。

## 开发与验证

```bash
npm test               # 物理、旋转、规则、搜索和反馈逻辑
npm run test:browser   # 真实界面的操作与击球流程
npm run test:gpu       # 真实 WebGPU 轨迹筛选、七种球局、精确出杆与 CPU 回退
npm run test:power     # 超过 100% 的控件、物理出杆、撤销与 CPU / GPU 搜索
npm run test:render    # 球面滚动、遮挡、高光与旋转标记
npm run build          # TypeScript 检查与生产构建
npm run screenshots    # 更新 README 中的三张展示截图
```

启动开发服务后，可运行 `node scripts/benchmark-search.mjs` 对比直球、组合球和扎杆局面的 CPU / GPU 总搜索耗时。脚本交替执行两轮，包含初始化、GPU 读回与 CPU 验证成本，报告保存至 `test-results/search-benchmark.json`。`test:gpu` 需要实际可用的 WebGPU，GPU 不可用时会明确失败，避免把 CPU 回退误认为 GPU 测试成功。

目前有 **57 项自动测试**，覆盖高速薄球、相向碰撞、四边贴库球、六袋进球、袋牙擦碰反弹、密集开球和规则边界，以及组合击点、跳球越障、扎杆弧线、抬杆角度自动细化、双库路线生成和超过 100% 的力度模拟与搜索。浏览器回归验证搜索与实际执行的球位和旋转姿态一致，也覆盖跳球与扎杆方案的参数同步、实际执行、出杆期间的操作锁定、落袋滚动动画、静音、撤销、全自动、黑八胜负，以及双人自由球的合法与非法放置等流程。

浏览器脚本默认使用本机 Chrome，服务未启动时会自动启动。可通过环境变量 `CUE_LAB_BROWSER=msedge` 使用 Edge，或通过 `CUE_LAB_TEST_URL` 指向已运行的服务。测试截图输出到被 Git 忽略的 `test-results/`；展示截图输出到随源码提交的 `docs/screenshots/`。
